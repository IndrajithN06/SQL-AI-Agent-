# SQLInsightsAgent

An AI-powered SQL agent that converts natural-language questions into SQL Server queries, validates them, executes them against a database, and automatically self-corrects failed queries using database errors and schema information.

The project uses a local LLM through Ollama and LangGraph to orchestrate the SQL generation, validation, execution, and self-correction workflow.

## Self-Correction

The agent does not rely only on the LLM's initial SQL generation.

When SQL Server returns an execution error, the self-correction node provides the LLM with:

* Original user question
* Previously generated SQL
* SQL Server execution error
* Database tables
* Table schemas and columns
* Database relationships
* SQL Server-specific rules

The LLM then generates a corrected query, which is sent back through validation and execution.

### Example

Initial SQL:

```sql
SELECT TOP 5 ProductName,
       SUM(OrderDetails.UnitPrice * OrderDetails.Quantity) AS TotalSales
FROM Products
JOIN OrderDetails
    ON Products.ProductID = OrderDetails.ProductID
JOIN Orders
    ON OrderDetails.OrderID = Orders.OrderID
GROUP BY ProductName
ORDER BY TotalSales DESC
```

SQL Server error:

```text
Invalid object name 'OrderDetails'.
```

The database schema contains the actual table:

```text
Order Details
```

The self-correction node generates:

```sql
SELECT TOP 5 ProductName,
       SUM([Order Details].UnitPrice * [Order Details].Quantity) AS TotalSales
FROM Products
JOIN [Order Details]
    ON Products.ProductID = [Order Details].ProductID
JOIN Orders
    ON [Order Details].OrderID = Orders.OrderID
GROUP BY ProductName
ORDER BY TotalSales DESC
```

The corrected query is validated and successfully executed.

## LangGraph Workflow

The workflow is implemented using four main nodes:

### 1. Generate SQL

Retrieves the database schema and relationships and sends them to the LLM along with the user's question.

```text
Question
   ↓
Schema + Relationships
   ↓
Ollama
   ↓
Generated SQL
```

### 2. Validate SQL

Checks the generated SQL against the application's SQL safety and validity rules before execution.

### 3. Execute SQL

Executes the query against SQL Server and stores either:

```text
Query Result
```

or:

```text
SQL Error
```

in the shared agent state.

### 4. Self-Correct SQL

Runs when validation fails or database execution returns an error.

The node sends the previous SQL, error information, and database schema back to the LLM and generates a corrected query.

A retry counter prevents infinite correction loops.

## Agent State

The LangGraph nodes communicate through a shared state containing information such as:

```text
question
sql
sql_valid
sql_error
query_result
retry_count
```

This allows each node to update the workflow without directly managing another node's execution.

## Retry Strategy

The agent allows a maximum of three self-correction attempts.

```text
Execution Error
      ↓
Self Correction
      ↓
Validation
      ↓
Execution
      ↓
Error?
   ┌──┴──┐
  Yes   No
   │     │
 Retry   END
```

This prevents the graph from entering an infinite loop when the LLM cannot produce a valid query.

## Running the Project

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd SQLInsightsAgent
```

### 2. Create a virtual environment

```bash
python -m venv .venv
```

Activate it on Windows:

```powershell
.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure environment variables

Create a `.env` file containing the required database and Ollama configuration.

The `.env` file is intentionally excluded from Git.

### 5. Start Ollama

Make sure Ollama is running locally and the required model is available.

Example:

```bash
ollama list
```

### 6. Run tests

Example:

```powershell
python -m tests.test_db
```

Run the complete agent workflow:

```powershell
python -m tests.test_graph
```

## Design Goals

This project focuses on understanding the fundamentals of an AI-powered database agent rather than building a large UI application.

The main goals are:

* Natural-language to SQL generation
* Schema-aware SQL generation
* SQL validation and safety
* Database execution
* Error-aware self-correction
* Retry handling
* Local LLM inference
* Stateful agent orchestration with LangGraph

## Future Improvements

Potential improvements include:

* Schema-aware table and column validation before execution
* Better SQL parsing and validation
* Query execution timeout handling
* Query performance monitoring
* Structured logging and observability
* Natural-language explanations of query results
* Hybrid SQL validation and LLM validation
* Evaluation dataset for SQL generation accuracy
* Prompt-injection protection
* API layer for exposing the agent as a service
* Web UI for interacting with the agent

## Disclaimer

This repository is a learning and engineering prototype demonstrating an agentic SQL workflow using local LLM inference. It is not intended to execute arbitrary write operations against production databases.
